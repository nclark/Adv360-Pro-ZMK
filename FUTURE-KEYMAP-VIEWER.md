# Keymap Viewer v2 (HTML popup, yabai scratchpad)

**Status: implemented 2026-09-03.** See `keymap-viewer/gen_keymap.py`,
`bin/show_keymap.sh`, the `keymap` target in the `Makefile`, and the
"Keymap Viewer" section of `CLAUDE.md`. The text below is the original plan.


Written 2026-08-31 by Claude, from work done in `~/workspace/projects/corne_4_1`.
This describes a keymap-viewer pattern that was built and proven for the Corne
V4.1 travel keyboard. Even if that board gets returned, the same pattern should
be ported to this repo for the Advantage 360 Pro. A future Claude session should
be able to implement this from the description below.

## What was built (and works) for the Corne

A zero-dependency toolchain: keymap file → single self-contained HTML page →
chromeless Chrome app window → yabai scratchpad toggled by an skhd hotkey.

Files to crib from in `~/workspace/projects/corne_4_1`:

- **`gen_keymap.py`** — python3 stdlib only. Parses the keymap source (there: a
  Vial `.vil` JSON file), renders one HTML page with:
  - hand-rolled physical geometry: a `GEO` dict of `(row, col) -> (x, y, w, h,
    rotation)` in key units; right half generated by mirroring the left
  - a keycode→legend translator (mod-taps show tap label + small mod symbol,
    layer-taps show the layer name, shifted keycodes render as `!@#$…`)
  - one `<section>` per layer: base plus one panel per hold-layer, with the
    layer's trigger key highlighted, transparent keys ghosted showing their
    base legend, and layer-defined keys tinted
  - JS: keys `1..N` jump to a layer, `←`/`→`/Space cycle, `Esc`/`q` closes,
    `document.body.style.zoom` auto-shrinks to fit narrow windows (capped at 1)
- **`show_keymap.sh`** — toggle script bound in skhd:
  ```sh
  yabai -m window --toggle corne-keymap 2>/dev/null && exit 0
  exec /Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
      --app="file://$PWD/keymap.html" >/dev/null 2>&1 &
  ```
  `--app=` gives a chromeless window whose title = the page `<title>`, which
  is what the yabai rule matches on.
- **yabai rule** (in `~/.config/yabai/yabairc`):
  ```
  yabai -m rule --add label=corne-keymap app="^Google Chrome$" \
    title="^Corne keymap$" scratchpad=corne-keymap manage=off sticky=on \
    sub-layer=above grid=24:24:5:7:13:11
  ```
  Scratchpad = summon/hide toggle, floats over tiles and fullscreen, centered
  by the grid. (Note: this yabai version wants `sub-layer`, not `layer`.)
- **skhd binding** (in `~/.config/skhd/skhdrc`):
  ```
  ctrl + alt + cmd + shift - c : $HOME/workspace/projects/corne_4_1/show_keymap.sh
  ```
- **Freshness**: the Corne's `push.sh` (applies layouts to the board) also
  reruns `gen_keymap.py`, so the page can never drift from the hardware. The
  Adv360 equivalent hook is the firmware build step (see below).

## Porting it to the Adv360

1. **Parse ZMK instead of Vial.** Source of truth is `config/adv360.keymap` +
   `config/layers/*.dtsi`. Easiest path: `keymap parse -z config/adv360.keymap`
   (keymap-drawer, already used by `bin/show_keymap.sh`) emits YAML with
   per-layer key lists — convert that to the JSON the generator consumes,
   rather than writing a devicetree parser. Custom behaviors (`&voiceink_all`,
   `hm_l`, `shift_const_l`, `&const_word`) need a legend table entry each.
2. **Geometry.** Build the `GEO` dict from `assets/key-positions.md` /
   `key-positions.png` (definitive position numbers). 76 keys, thumb clusters
   rotated; mirror trick works here too.
3. **Reuse the exact popup plumbing.** New title (e.g. `Adv360 keymap`), new
   yabai rule label, and rebind the existing hotkey:
   - `ctrl + alt + cmd + shift - k` in skhdrc currently points at
     `bin/show_keymap`, which does not exist (the file is `show_keymap.sh`) —
     the binding has been silently dead. Point it at the new toggle script.
4. **Regenerate on build.** Hook the generator into the `Makefile` so every
   firmware build refreshes the HTML, mirroring the Corne's push-hook.
5. **Prior art in this repo:** `kmviewer/` is a Go/Bubble Tea TUI that shows
   pre-rendered layer PNGs via kitty graphics, and
   `bin/generate_layer_images.sh` + `bin/show_keymap.sh` are the
   keymap-drawer SVG path. The HTML-popup approach supersedes both: no kitty
   dependency, no pre-rendered images, layer switching with number/arrow keys,
   works over fullscreen via yabai scratchpad.

## UX spec (what the user liked, keep it)

- One layer visible at a time; `1..N` direct-jump, arrows/Space cycle
- Chromeless, centered, floats above tiling AND native fullscreen, sticky
  across spaces; hotkey toggles (summon / hide); Esc closes
- Dark theme; hold-actions shown as small green sublabels; transparent keys
  ghosted; the held trigger key highlighted amber
- Auto-zoom so the board always fits the window width at ≤100%
